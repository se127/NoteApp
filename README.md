# NoteApp

یک برنامهٔ دسکتاپ یادداشت‌نویسی با Electron. رابط کاربری فارسی و راست‌به‌چپ (`fa-IR`) است و با shadcn/ui روی Tailwind CSS v4 ساخته شده.

## پشته

- Electron 44 — پروسهٔ اصلی و preload به‌صورت جاوااسکریپت خالص، بدون باندلر
- React 19 + TypeScript + Vite 8 با React Compiler فعال
- Tailwind CSS v4 به‌همراه مرتب‌کنندهٔ کلاس‌های `prettier-plugin-tailwindcss`
- shadcn/ui با سبک `radix-nova` و `rtl: true`
- Tiptap برای ویرایشگر متن یادداشت
- SQLite از طریق `node:sqlite`؛ چون با Node داخلی Electron عرضه می‌شود، هیچ ماژول نیتیویی برای کامپایل یا بازسازی وجود ندارد

## دستورها

از [bun](https://bun.sh) استفاده کنید — نه npm، نه yarn و نه pnpm.

| دستور                  | توضیح                                                       |
| ---------------------- | ----------------------------------------------------------- |
| `bun run dev`          | Vite را بالا می‌آورد و سپس برنامه را در Electron باز می‌کند |
| `bun run dev:web`      | فقط رندرر، در مرورگر روی `localhost:5173`                   |
| `bun run build`        | `tsc -b && vite build` — هم بررسی نوع و هم بیلد رندرر       |
| `bun test --parallel`  | کل مجموعهٔ تست‌ها با Bun                                    |
| `bun run lint`         | oxlint                                                      |
| `bun run format`       | Prettier، شامل مرتب‌سازی کلاس‌های Tailwind                  |
| `bun run format:check` | بررسی قالب‌بندی بدون تغییر فایل‌ها                          |
| `bun run preview`      | پیش‌نمایش خروجی build روی سرور محلی                         |

با `ctrl+c` متوقف کنید. اسکریپت ابتدا درخواست بستن را به‌صورت عادی به پنجره می‌فرستد تا پایگاه داده درست بسته شود، و تنها پس از یک مهلت کوتاه باقی‌مانده‌ها را به اجبار می‌کشد. به این ترتیب پورت ۵۱۷۳ آزاد و پنجره بسته می‌شود و اجرای بعدی روی همان پورت بالا می‌آید.

پیش از هر commit باید `bun run build` و `bun test --parallel` اجرا شوند. قلاب pre-commit هیچ‌کدام را اجرا نمی‌کند، پس تنها جایی است که خطاهای نوع گرفته می‌شوند — از جمله خطاهای نوع در `tests/`، چون `tsconfig.test.json` آن‌ها را هم در همان build بررسی می‌کند.

قالب‌بندی و lint را لازم نیست دستی اجرا کنید: قلاب pre-commit هر دو را روی فایل‌های staged انجام می‌دهد و موارد را خودکار اصلاح می‌کند. این قلاب از دستورهای مستقل سخت‌گیرانه‌تر است، چون `--deny-warnings` دارد؛ یعنی هشداری که `bun run lint` از آن عبور می‌کند، commit را متوقف می‌کند. جزئیات در `lint-staged.config.mjs`.

## ساختار پروژه

```
electron/   پروسهٔ اصلی، پل preload و دسترسی به SQLite
scripts/    هماهنگ‌کنندهٔ توسعه و هماهنگ‌کنندهٔ بسته‌بندی
src/components/     کامپوننت‌های اختصاصی برنامه
src/components/ui/  کامپوننت‌های vendored شدهٔ shadcn — هرگز ویرایش دستی نکنید
src/pages/           صفحهٔ فهرست یادداشت‌ها و صفحهٔ ویرایش یادداشت
src/hooks/           بارگذاری یادداشت‌ها از پل IPC
src/lib/             منطق خالص: notes، theme، notes-store، note-body، shortcuts و…
src/font/vazirmatn/   Vazirmatn روی خود سرور (فارسی + ارقام، بدون لاتین)
src/note-body.css    استایل متن یادداشت
tests/               تست‌ها؛ tests/helpers پایه‌های مشترک، tests/setup راه‌اندازی happy-dom
bunfig.toml          preload تست‌ها؛ بدون آن تست‌های کامپوننتی document ندارند
```

قلم‌ها بر اساس هر گلیف انتخاب می‌شوند: Vazirmatn برای خط عربی، Inter برای لاتین و در نهایت `sans-serif` به‌عنوان جایگزین.

## رفتار برنامه

- متن یادداشت یک ویرایشگر Tiptap در `src/components/note-body-editor.tsx` است و یک نوار ابزار همیشه‌نمایان بالای متن دارد (نه منوی شناور): undo و redo، جهت متن، سبک بلوک، اندازهٔ متن، چهار قالب، رنگ متن و رنگ پس زمینه، دو فهرست، تراز متن، موقعیت متن، خط افقی و ایموجی. سبک بلوک کار جاری را به پاراگراف یا عنوان `h2` تا `h6` تبدیل می‌کند؛ `h1` وجود ندارد چون عنوان یادداشت همان نقش را دارد. داخل عنوان‌ها، اندازهٔ متن، ضخیم و هر دو دکمهٔ فهرست غیرفعال می‌شوند.
- انتخاب یک مقدار از سبک بلوک یا اندازهٔ متن، مکان‌نما را به ویرایشگر برمی‌گرداند و متن بعدی با مقدار تازه نوشته می‌شود؛ متن موجود دست‌نخورده می‌ماند.
- متن یادداشت به‌صورت HTML ذخیره می‌شود. `isStoredHtml` در `src/lib/note-body.ts` تشخیص می‌دهد متن ذخیره‌شده markup است یا متن ساده.
- عنوان یادداشت یک `div` قابل ویرایش ساده است و هیچ قالبی ندارد. عنوان همیشه اجباری است و متن اختیاری؛ هیچ محدودیت طولی اعمال نمی‌شود.
- ذخیرهٔ خودکار با تأخیر ۸۰۰ میلی‌ثانیه پس از آخرین تغییر انجام می‌شود، همراه با نشانگر وضعیت ذخیره. دکمهٔ «بازگشت به یادداشت ها» هم پیش از رفتن به فهرست، ذخیرهٔ معلق را بی‌درنگ می‌نویسد و اگر شکست بخورد در ویرایشگر می‌ماند.
- صفحهٔ اصلی فهرست یادداشت‌هاست: یک جدول shadcn با عنوان چندخطی، زمان ایجاد نسبی («۶ روز ی پیش») و منوی «حذف» در هر ردیف. زمان نسبی و زمان کامل با تقویم هجری شمسی در `src/lib/relative-time.ts` ساخته می‌شوند؛ زمان کامل در tooltip همان ستون نشان داده می‌شود. نوار بالای برنامه در هر دو صفحه یکسان است: دکمهٔ پوسته در چپ و دکمهٔ میان‌برها در راست.
- `ctrl+s` یادداشت را بی‌درنگ ذخیره می‌کند و تأخیر معلق را لغو می‌کند. `ctrl+n` دقیقاً همان کاری را می‌کند که دکمهٔ «یادداشت جدید» می‌کند. هر دو میانبر روی **کلید فیزیکی** (`event.code`) تطبیق می‌خورند، نه فقط روی `event.key`، چون در چیدمان فارسی کلید S به‌جای `s` حرف «س» برمی‌گرداند.
- هر دکمهٔ نوار ابزار متن، انتخابگر ایموجیِ متن و انتخابگر ایموجیِ عنوان میانبر دارند. میانبرهایی که به یک منو یا فهرست باز می‌شوند (جهت متن، سبک بلوک، اندازهٔ متن، تراز متن، موقعیت متن، هر دو رنگ و هر دو ایموجی) همان کار دکمه را می‌کنند: منو را باز می‌کنند تا انتخاب را خودتان انجام دهید. ترکیب هر میانبر در راهنمای همان دکمه نوشته شده است.
- همهٔ میانبرها یک‌بار در `src/lib/shortcuts.ts` تعریف می‌شوند: پنجرهٔ میان‌برها، راهنماها و کلیدهای واقعی از همان یک منبع می‌خوانند، پس فهرست مستند نمی‌تواند از رفتار واقعی عقب بماند. میانبرهای `Ctrl+Alt` روی ویندوز انتخاب شده‌اند چون کلیدهای `Ctrl+Shift` را مرورگر و ابزارهای توسعهٔ خودشان ادعا می‌کنند؛ میانبرهای عددی هم به همان دلیل روی حروف‌اند، چون کلیدهای عددیِ صفحه‌کلید عددی با ترکیب `Ctrl+Shift` روی ویندوز قابل اتکا نبودند.
- Tab در ویرایشگر به‌ترتیب از عنوان یادداشت به انتخابگر ایموجی و سپس کنترل‌های نوار ابزار می‌رود؛ `Enter` در عنوان مکان‌نما را به متن می‌برد.
- تم سیستم (روشن/تیره/پیروی از سیستم) با `theme-toggle` و `theme-provider` پیاده‌سازی شده و از طریق IPC در `theme.json` ذخیره می‌شود.
- تأیید حذف یادداشت با `AlertDialog` قبل از پاک‌کردن انجام می‌شود؛ منوی سه‌نقطهٔ هر ردیف جدول همان کاری را می‌کند که قبلاً منوی سایدبار می‌کرد.
- پنجره همیشه بیشینه باز می‌شود و کمینهٔ آن ۸۰۰×۶۰۰ است؛ سقفی برای بزرگ‌شدن وجود ندارد.

## پایگاه دادهٔ حالت توسعه با نسخهٔ نصب‌شده فرق دارد

`scripts/dev.ts` هنگام اجرای برنامه در حالت توسعه متغیر `NoteApp_USER_DATA` را تنظیم می‌کند و `electron/main.mjs` پیش از باز کردن پایگاه داده مسیر `userData` را روی آن می‌گذارد. بنابراین:

| اجرا          | مسیر داده روی ویندوز    |
| ------------- | ----------------------- |
| `bun run dev` | `%APPDATA%\NoteApp-dev` |
| نسخهٔ نصب‌شده | `%APPDATA%\NoteApp`     |

پایگاه داده، یادداشت‌ها و پوسته در این دو پوشه کاملاً جدا هستند، پس یک باگ در حالت توسعه نمی‌تواند داده‌های نسخهٔ نصب‌شده را خراب کند.

این کار لازم است چون electron_builder مقدار `productName` را داخل `package.json` بسته‌بندی‌شده نمی‌نویسد. در نتیجه `app.getName()` در هر دو حالت `NoteApp` برمی‌گرداند و هر دو به یک پوشهٔ `userData` اشاره می‌کنند. `productName` فقط نام فایل اجرایی، میان‌برها و پوشهٔ نصب را تغییر می‌دهد، نه مسیر داده‌ها.

## بسته‌بندی برای ویندوز

| دستور                       | توضیح                                                          |
| --------------------------- | -------------------------------------------------------------- |
| `bun run build:windows`     | نصب‌کنندهٔ NSIS به‌صورت یک فایل `.exe` در `release/`           |
| `bun run build:windows:dir` | پوشهٔ باز و قابل اجرای `release/win-unpacked/`، بدون نصب‌کننده |

خروجی یک نصب‌کنندهٔ تک‌کلیکی است: کاربر روی آن دوبار کلیک می‌کند و برنامه به‌صورت per-user در `%LOCALAPPDATA%\Programs\NoteApp` نصب می‌شود، بنابراین هیچ درخواست رمز مدیر سیستمی نشان داده نمی‌شود. میان‌بر دسکتاپ و منوی استارت ساخته می‌شود و حذف‌کننده‌ای هم در بخش Apps & features ثبت می‌شود. اگر می‌خواهید کاربر مسیر نصب را انتخاب کند، در `electron-builder.yml` مقدار `oneClick: false` را بگذارید؛ NSIS فقط در نصب‌کنندهٔ راهنما انتخاب مسیر را نشان می‌دهد.

داده‌های کاربر با حذف برنامه پاک نمی‌شود، چون `deleteAppDataOnUninstall` روی `false` است. برای پاک کردن کامل، کاربر باید پوشهٔ `%APPDATA%\NoteApp` را حذف کند.

پیکربندی در `electron-builder.yml` است و خروجی در `release/` قرار می‌گیرد که در gitignore شده. هنوز آیکونی ثبت نشده، بنابراین ویندوز آیکون پیش‌فرض Electron را نشان می‌دهد؛ برای جایگزینی، یک `build/icon.ico` اضافه کنید. این نسخه فقط برای معماری x64 ساخته می‌شود.

### نیازمندی wine برای ساخت روی لینوکس یا مک

نصب‌کنندهٔ NSIS یک فایل اجرایی ۳۲ بیتی است و electron-builder باید آن را زیر wine اجرا کند تا حذف‌کننده را بسازد. به همین دلیل wine باید بخش **۳۲ بیتی** را هم داشته باشد؛ در غیر این صورت ساخت با خطای `failed to load C:\windows\syswow64\ntdll.dll` در انتها شکست می‌خورد. روی دبیان و اوبونتو:

```
sudo dpkg --add-architecture i386
sudo apt update
sudo apt install wine32:i386
WINEARCH=win64 wineboot -u   # یک‌بار برای ساخت prefix
```

اگر wine از قبل نصب است ولی `syswow64` خالی است، باید prefix را از نو ساخت: `rm -rf ~/.wine` و بعد `wineboot -i` بدون تنظیم `WINEARCH`.

`scripts/build.ts` پیش از شروع، وجود wine و پشتیبانی ۳۲ بیتی را بررسی می‌کند تا این خطا بعد از چند دقیقه فشرده‌سازی ظاهر نشود. روی خود ویندوز هیچ ابزار اضافه‌ای لازم نیست.

### چه چیزی به کاربر بدهیم

فقط یک فایل: `release/NoteApp-<version>.exe`. پوشهٔ `win-unpacked/` خروجی داخلی ساخت است و توزیع نمی‌شود، و فایل `.blockmap` هم فقط برای به‌روزرسانی خودکار است که در این پروژه تنظیم نشده.

هیچ گواهی امضای کدی وجود ندارد، پس SmartScreen ویندوز در اجرای اول هشدار می‌دهد و کاربر باید آن را با _More info_ → _Run anyway_ نادیده بگیرد. این را حتماً همراه فایل توضیح دهید، وگرنه فایل بدافزار به نظر می‌رسد.

## نکات

- `bun run dev` تنها یک اجراکننده است؛ برای توقف، `ctrl+c` بزنید. کشتن آن با اجبار به درخت فرزند روی ویندوز انجام می‌شود، پس اگر چیزی باقی بماند، دستور خودش خطا می‌دهد.
- اگر پنجره‌ای باز نشد ولی ترمینال خطا نداد، احتمالاً نمونهٔ دیگری از برنامه هنوز اجراست. `electron/main.mjs` قفل تک‌نمونه‌ای می‌گیرد و نسخهٔ دوم بدون باز کردن پنجره خارج می‌شود.
- هر تغییری زیر `electron/` فقط پس از بستن کامل برنامه و اجرای دوباره اثر می‌کند؛ HMR فقط رندرر را دوباره بارگذاری می‌کند. نشانهٔ یک پروسهٔ اصلی کهنه، خطای `No handler registered for 'notes:list'` در کنسول رندرر است.
- رندرر با `contextIsolation: true`، `nodeIntegration: false` و `sandbox: true` اجرا می‌شود. به‌جای فعال کردن Node در صفحه، پل preload را گسترش دهید. preload باید CommonJS بماند؛ preload به‌صورت ESM و در حالت sandbox بی‌صدا اجرا نمی‌شود.
- در `vite.config.ts` مقدار `base: "./"` تنظیم شده است. برنامهٔ بسته‌بندی‌شده `dist/index.html` را از طریق `file://` باز می‌کند و مسیرهای مطلق `/assets/...` به ریشهٔ درایو اشاره می‌کنند و پنجره سفید می‌ماند. به همین دلیل در `src/main.tsx` از `HashRouter` استفاده می‌شود، نه `BrowserRouter`.
- `src/components/ui/**` از Prettier و oxlint مستثنا شده تا به‌روزرسانی‌های shadcn با قالب‌بندی محلی تضاد پیدا نکنند. هر تغییری در این پوشه با `bunx shadcn@latest` انجام شود، وگرنه بازنویسی می‌شود.
- پوشهٔ `node_modules` بین لینوکس و ویندوز قابل انتقال نیست. `bun install` باینری مخصوص هر سیستم‌عامل را داخل `node_modules/electron/dist` می‌گذارد، پس کپی کردن پوشه باعث می‌شود `bunx electron` باینری غلط را پیدا کند و پنجره‌ای باز نشود. نشانهٔ آن نبودن `node_modules/electron/path.txt` است؛ در این حالت اجرا با خطای _Electron failed to install correctly_ متوقف می‌شود. درمان: پوشهٔ `node_modules/electron` را حذف و دوباره `bun install` را اجرا کنید.
